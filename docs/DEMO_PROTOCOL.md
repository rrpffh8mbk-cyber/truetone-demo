# 试色有谱演示与验证协议

## 一句话与主流程

同一支口红，哪条试色值得参考？正式演示顺序：图像处理线索 → 图文一致性 → 同产品真实证据 → 个性化参考 → 下一步核验建议。先打开 [篡改风险测试台](https://rrpffh8mbk-cyber.github.io/truetone-demo/forensics.html)，再演示下面三组内容案例。自拍预览放在观众想继续体验时，不作为技术核心。

## 已知三案例演示

案例原文和图片来自组员提供的 `TrueTone_Demo_3_Case_Evaluation.docx`。图片为该文档中的对应配图，做了网页尺寸压缩；原文未改写。所有案例使用黄皮 / 深唇 / 淡妆的示例条件，与真实用户设置分开。点击一键体验实际执行相同的图像、文字和排序流程；允许修改正文后重新分析。

1. **夸张种草 · YSL 610**：看绝对适配和性能承诺，以及对应评价原文。颜色相似不能覆盖文案风险。
2. **版本混淆 · 兰蔻 274**：不主动输入版本。正文优缺点均保留，明确版本无法确定；家族证据不得冒充特定版本结论。
3. **具体体验 · YSL 610**：看黄皮/深唇/淡妆自述、时间变化和正反体验。负面词不导致“不可信”判决。

合理预期是三个文字参考分有明显区别，不要求固定数字；图片分独立由标准色差决定，可以与文字顺序不同。结论不是把这三组强制排成一个真伪榜。

每次记录代码版本、案例文件哈希、数据目录哈希、模型版本、实际选区状态、颜色分、文字分、文字各项依据和产品版本。界面/API 不读取保存的结果文件作为答案。自动检查不能替代人工真实标签。

## 文字参考分公开规则

信息量合计最多 100：本人唇色、肤色、妆面各 10；涂抹厚度 10；颜色描述 12；时间或使用变化 12；具体体验 12；优缺点同时交代 12；表达边界 12。风险扣分：每类绝对承诺 15，泛化或情绪推荐每类 8；274 版本未确定扣 8。出现一类绝对承诺上限 65，多类上限 35。最终 max(0, 信息量 − 风险扣分)，再应用上限。不是测得的真伪概率。

自然光、原相机、无滤镜声明不增加分数；仅凭成片无法证明。负面体验贡献具体信息。只展示同产品且非跨版本归属的反例；引用时保留版本与原文，不把个人差异当成单独证伪依据。

## 现在已经验证什么

回归检查验证颜色公式、蓝唇 0 分、唇部失败不强行计分、当前标签优先级、评论原文与版本边界、参考图排序和手机页面流程。三个固定案例是已知压力测试，规则设计时已经看过案例，不能宣称是独立测试集。

新增受控操作验证：24 个原帖组分开调参与保留测试，冻结阈值后局部编辑检出 40/60，正常处理误报 0/48；已知生成图触发 0/6。详见 [受控报告](forensics/benchmark-report.md)；这不是来源真实性 ground truth，也不是任意图像盲测。

未完成：独立人工真值、真实世界盲评、通用误判率/准确率、跨色号泛化或商业转化实验。4 个已覆盖色号的深度原型不等于通用美妆 UGC 可信度系统。

## 下一步独立验证（待执行）

- 在冻结规则后按原始帖子/评价分组抽样，避免同一来源的照片或文本同时出现在调试和验证侧。
- 使用未参与规则调试的新帖子、不同版本和新色号；未收录产品先标记“证据不足”，不拿最近色号替代。
- 至少两名评估者先独立给“颜色可比较性、表达边界、使用条件信息量、对指定用户的参考价值”标注，再讨论分歧。不要让评估者看到系统分数。
- 报告样本量、来源/版本覆盖、评估者一致性与各项误判；置信区间和误差样例一并给出。不存在可靠真伪标签时不报告真伪准确率。
- 记录分割失败、光照、滤镜、原生唇色未知和版本不明的失败类型，验证后再调整；调试后的规则需重新在另一批数据验证。

## 品牌交付与商业验证（待执行）

报告下载的清单把具体证据连接到素材补拍、条件说明和版本标注，并列出图片/评价 ID。品牌可安排实际素材改版、统一条件使用测试与独立理解度评估。之后做同条件 A/B 测试，记录理解度、转化、退换原因、样本量与不确定性。当前只交付证据清单，没有自动部署或转化提升结果。

## 同期更新的保留

保留仓库同期加入的图文冷暖/浓淡/多图对照与最近样本色差计算，移动到 cross-modal.js。它们只作为辅助依据单独解释，不合成多模态真假总分。自然光、原相机和无滤镜仍是无法仅凭成片验证的声明。
